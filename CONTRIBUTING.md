Contributing

Thanks for looking. These are small, independent projects, so here's what'sactually useful and what to expect.

## Before anything else: read the repo's README

Especially on the hardware projects. `slipstream` and `divergent-house-bus`involve high-voltage battery systems and, in one case, a combustion appliance.Those READMEs carry safety context, and a suggestion made without it usuallycan't be evaluated.

## What's most useful

**Corrections.** If a number is wrong, a source is misread, or a calculationdoesn't hold, say so. This is the single most valuable contribution to any ofthese projects and it gets acted on. You don't need to supply a fix — just showthe problem.

**Real-world data.** Several projects publish *researched estimates* clearlylabelled as estimates. If you've built something similar and have measurednumbers, those replace guesses, and that's a significant upgrade.

**Questions that expose an assumption.** "Why sodium-ion?" or "what happens ifthe loop fails at night?" are contributions. If the answer isn't in the docs,the docs are incomplete.

## Opening an issue

Use the templates. They exist to make sure a report contains the thing needed toact on it — mostly: what you expected, what happened, and enough detail toreproduce or locate it.

One issue per subject. A single issue containing five unrelated points is veryhard to close.

## Pull requests

* **Open an issue first for anything substantial.** A PR that redesigns asubsystem is a lot of your effort to spend before finding out whether thedirection is wanted.
* **Small and focused merges faster.** One change per PR.
* **Match the surrounding style.** No repo here uses a strict style guide;looking like the code around it is enough.
* **Say what you tested.** Even "opened it and clicked through" is information."I didn't test this" is also fine, if you say so.

## What to expect back

These are maintained by one person alongside a publishing schedule. Responsetime varies from a day to a couple of weeks. If something has gone quiet formore than that, a nudge on the thread is welcome and not rude.

Not every PR gets merged. If yours doesn't, you'll get an actual reason ratherthan silence.

## Licensing

Contributions are made under the licence of the repository you're contributingto. The projects here use different licences depending on what they are —hardware under CERN-OHL-S, code under MIT or AGPL, docs under CC-BY — so checkthat repo's `LICENSE` before contributing.

## Conduct

Be decent. Assume the other person is trying. The full policy is in`CODE_OF_CONDUCT.md`.
